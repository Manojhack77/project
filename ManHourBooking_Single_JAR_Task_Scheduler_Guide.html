ManHourBooking: one JAR, Task Scheduler and the local network

Complete procedure for Windows: combine the React frontend and the Spring Boot backend into one JAR, start it automatically with Task Scheduler, and let everyone on the local network use it through the server's IP address.

1. What you will build

At the end there is one file, manhourbooking-backend-1.0.0.jar. It contains the Spring Boot backend and the built React website. You copy it to one Windows computer (the server), and Windows Task Scheduler starts it automatically every time that computer boots. Everyone else on the local network opens it in a browser with the server's IP address, for example http://192.168.1.50:8080.

Because the website and the API come from the same address, there are no CORS problems and users only need to remember one address.

Note: This procedure was written by reading your project (Spring Boot 3.3.5, Java 17, MySQL, Vite/React) and was not run on your computers. Follow the checks in section 9 after each stage. Where a command differs on your system (Java path, MySQL path, IP range) it is marked.

3. One-time code changes (three small edits)

The project was built to run as two separate programs, so three things must change before the website can live inside the backend. Make them once, then build.

3.1 Frontend: use the same address for the API

File manhourbooking-frontend/src/config.js. Today the address http://localhost:8080 is used when no setting exists, which would break for every other computer. Replace the last line with:

// In the built (production) site the API is on the same address as the page, so the base is empty.
// While developing (npm run dev) it is the backend on this computer. VITE_API_URL can still override both.
export const API_URL = import.meta.env.VITE_API_URL ?? (import.meta.env.PROD ? "" : "http://localhost:8080");

3.2 Backend: let Spring Boot show the website pages

Create a new file manhourbooking-backend/src/main/java/com/manhour/web/SpaController.java. It makes a browser refresh on /login, /staff or /admin open the React page instead of an error. (The home page / is served by Spring Boot automatically.)

package com.manhour.web;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

/** The pages of the React app. A browser refresh on one of them must return index.html. */
@Controller
public class SpaController {
    @GetMapping({"/login", "/staff", "/admin"})
    public String app() {
        return "forward:/index.html";
    }
}

3.3 Backend: allow those pages and files through the security rules

File manhourbooking-backend/src/main/java/com/manhour/config/SecurityConfig.java. Today every address that is not under /api is denied. Add one line just before .anyRequest().denyAll()):

.requestMatchers(HttpMethod.GET, "/", "/index.html", "/favicon.svg", "/assets/**",
        "/login", "/staff", "/admin").permitAll()

The result should look like this (only the new lines are marked):

.requestMatchers("/api/admin/**").hasRole("ADMIN")
.requestMatchers(HttpMethod.GET, "/", "/index.html", "/favicon.svg", "/assets/**",
        "/login", "/staff", "/admin").permitAll()          // new
.anyRequest().denyAll())
Tip: These pages contain no data. All data still comes from /api/**, which keeps its login and role rules unchanged.

4. Build the JAR (on the build PC)

4.1 The easy way: a build script

Create build-jar.bat in the folder that contains manhourbooking-frontend and manhourbooking-backend:

@echo off
setlocal
set ROOT=%~dp0

echo === 1/4 Frontend: install and build ===
cd /d "%ROOT%manhourbooking-frontend" || exit /b 1
call npm ci || exit /b 1
call npm run build || exit /b 1

echo === 2/4 Copy the built website into the backend ===
set STATIC=%ROOT%manhourbooking-backend\src\main\resources\static
if exist "%STATIC%" rmdir /s /q "%STATIC%"
mkdir "%STATIC%"
xcopy /e /i /y "%ROOT%manhourbooking-frontend\dist\*" "%STATIC%\" || exit /b 1

echo === 3/4 Backend: build the JAR ===
cd /d "%ROOT%manhourbooking-backend" || exit /b 1
call mvn -q clean package -DskipTests || exit /b 1

echo === 4/4 Done. Your file is: ===
echo %ROOT%manhourbooking-backend\target\manhourbooking-backend-1.0.0.jar
endlocal

Double-click it, or run it from a terminal. It takes a few minutes the first time because Maven and npm download their libraries.

4.2 The same thing by hand

cd manhourbooking-frontend
npm ci
npm run build
:: copy everything inside dist\ into manhourbooking-backend\src\main\resources\static\
cd ..\manhourbooking-backend
mvn clean package -DskipTests

The result is manhourbooking-backend\target\manhourbooking-backend-1.0.0.jar. You can open it with 7-Zip: under BOOT-INF\classes\static you should see index.html and an assets folder. If they are missing, step 2 did not copy the website.

Watch out: If npm ci fails on a platform or "lock file" error, delete node_modules and package-lock.json and run npm install instead. Do not build the JAR before the website is in static, or the JAR will only contain the API.
Tip: Run the build again after every change to the frontend or backend, then replace the JAR on the server (section 10).

5. Prepare the server

5.1 Install Java and MySQL

  1. Install JDK or JRE 17 or newer. Note its path, for example C:\Program Files\Eclipse Adoptium\jdk-17.0.x\bin\java.exe.
  2. Install MySQL 8 as a Windows service with "Start the server at system startup" selected (this is the default in the installer).
  3. Set the Windows time zone to your local one (for example India Standard Time). The app uses the computer's date for "current month" and for project expiry.

5.2 Create the database and a dedicated user

Open a MySQL prompt as root and run (choose your own password):

CREATE DATABASE IF NOT EXISTS manhourbooking CHARACTER SET utf8mb4;
CREATE USER 'manhour'@'localhost' IDENTIFIED BY 'ChangeThisDbPassword';
GRANT ALL PRIVILEGES ON manhourbooking.* TO 'manhour'@'localhost';
FLUSH PRIVILEGES;

The tables are created by the application itself the first time it starts. Do not use the MySQL root user for the app.

5.3 Create the application folder

C:\ManHour\
    manhourbooking-backend-1.0.0.jar     <- copy the JAR here
    start-manhour.bat                    <- created in 5.4
    logs\                                <- created automatically

5.4 The start script C:\ManHour\start-manhour.bat

Task Scheduler will run this file. It holds the settings (they are not stored in the JAR). Edit the three marked values.

@echo off
cd /d C:\ManHour
if not exist logs mkdir logs

rem ---- settings: CHANGE THESE ----
set "DB_USER=manhour"
set "DB_PASSWORD=ChangeThisDbPassword"
set "JWT_SECRET=PUT-A-LONG-RANDOM-TEXT-HERE-AT-LEAST-32-CHARACTERS"
set "DEFAULT_PASSWORD=Welcome@123"
rem set "SERVER_PORT=80"
rem set "SPRING_DATASOURCE_URL=jdbc:mysql://DBSERVER:3306/manhourbooking?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC"

"C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot\bin\java.exe" -Xms256m -Xmx512m -jar C:\ManHour\manhourbooking-backend-1.0.0.jar >> C:\ManHour\logs\app.log 2>&1
  • Use the full path to java.exe. The scheduled task may run as the SYSTEM account, which does not have your PATH.
  • JWT_SECRET signs the login tokens. If you leave the built-in value anyone who knows it could create valid tokens. Generate a good one in PowerShell:
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
  • DB_USER / DB_PASSWORD must match step 5.2. Keep the quotes around values; they protect characters such as &.
  • CORS_ORIGINS is not needed because the website and API now share one address.
  • If MySQL runs on another computer, remove the rem in front of SPRING_DATASOURCE_URL and put that computer's name or IP.

5.5 Test it by hand first

Open a Command Prompt, run C:\ManHour\start-manhour.bat and wait for the line "Started ManHourBookingApplication". Open http://localhost:8080 on the server and log in with ADMIN01 / admin123 (change it right away with Change password). Stop it with Ctrl+C. Only continue when this works.

6. Network: IP address, firewall and name

6.1 Fix the server's IP address

Find it with ipconfig (IPv4 Address, for example 192.168.1.50). Make it permanent in one of two ways:

  • DHCP reservation (best): in the router or DHCP server, bind that IP to the server's MAC address.
  • Static IP on the server: Network adapter, Properties, Internet Protocol Version 4, "Use the following IP address", with the same subnet mask, gateway and DNS as before. Ask your network administrator for a free address.

6.2 Open the firewall for your local network only

Run in an Administrator Command Prompt. Change the range to your own network, for example 192.168.1.0/24:

netsh advfirewall firewall add rule name="ManHourBooking 8080" dir=in action=allow protocol=TCP localport=8080 profile=private,domain remoteip=192.168.1.0/24

If Windows classes your network as "Public", change it to "Private" in Settings, or add public to the profile= list.

6.3 Users open the address

Give everyone http://192.168.1.50:8080 (your server's IP). Staff can add it to their browser bookmarks or desktop.

6.4 Optional: a friendly name instead of the IP

  • Ask whoever manages your DNS to add an A record such as manhour.yourcompany.local pointing to the server's IP. Then users type http://manhour.yourcompany.local:8080.
  • For a single computer you can instead add a line to C:\Windows\System32\drivers\etc\hosts: 192.168.1.50 manhour.local.
  • Without :8080: set SERVER_PORT=80 in the start script, and change the firewall rule to port 80. Port 80 must not already be used (IIS or another web server).

7. Add the JAR to Task Scheduler

The task runs start-manhour.bat at every boot, with no one logged in, and restarts it if it stops.

7.1 With the screens

  1. Press Win+R, type taskschd.msc, Enter.
  2. Choose Action, Create Task... (not "Create Basic Task").
  3. General tab: Name ManHourBooking. Choose Run whether user is logged on or not and tick Run with highest privileges. Click Change User or Group..., type SYSTEM, OK. Set "Configure for" to your Windows version.
  4. Triggers tab: New... Begin the task: At startup. Tick Delay task for and choose 1 minute (this gives MySQL time to start). OK.
  5. Actions tab: New... Action: Start a program. Program/script: C:\ManHour\start-manhour.bat. Start in: C:\ManHour. OK.
  6. Conditions tab: untick Start the task only if the computer is on AC power (important on laptops).
  7. Settings tab:
    • Tick Allow task to be run on demand.
    • Tick If the task fails, restart every 1 minute, Attempt to restart up to 5 times.
    • Untick "Stop the task if it runs longer than". By default Windows stops it after 3 days.
    • "If the task is already running": Do not start a new instance.
  8. Click OK. Enter an administrator password if asked.
  9. Right-click the task and choose Run. After about a minute the status shows Running.

7.2 The same with one command

Run in an Administrator Command Prompt. Then open the task and set the "restart if it fails" and "do not stop after 3 days" options from step 7.1 (the command cannot set them).

schtasks /Create /TN "ManHourBooking" /TR "C:\ManHour\start-manhour.bat" /SC ONSTART /DELAY 0001:00 /RU SYSTEM /RL HIGHEST /F

8. Check that everything works

  1. On the server open http://localhost:8080. The login page appears.
  2. Log in as ADMIN01 and open the Dashboard, Projects, Member mapping and Staff and rates tabs.
  3. On the server press F5 while on /admin. The page must reload, not show an error.
  4. From another PC on the network open http://SERVER-IP:8080. Log in and open the dashboard.
  5. Click Export Excel on the dashboard and open the file.
  6. Reboot the server and wait two minutes without logging in. Open the address from another PC. The app should be up. This is the real test of the scheduled task.
  7. Stop MySQL and the app, start only the server, and check that the app still comes up (the delay and the restart settings cover this).

9. Updating and backing up

9.1 Install a new version

  1. On the build PC run build-jar.bat again.
  2. On the server: schtasks /End /TN "ManHourBooking", then check tasklist | findstr java shows nothing from this app.
  3. Rename the old JAR to manhourbooking-backend-1.0.0.jar.old and copy the new JAR in with the same name.
  4. schtasks /Run /TN "ManHourBooking" and read the log.
  5. If something is wrong, put the .old file back.

Database tables are updated automatically. Keep a database backup before every update.

9.2 A daily database backup (also a scheduled task)

C:\ManHour\backup.cnf (keeps the password off the command line; restrict who can read this file):

[client]
user=manhour
password=ChangeThisDbPassword

C:\ManHour\backup.bat (change the MySQL path to match your version):

@echo off
for /f %%i in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd"') do set STAMP=%%i
if not exist C:\ManHour\backup mkdir C:\ManHour\backup
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" --defaults-extra-file=C:\ManHour\backup.cnf --single-transaction manhourbooking > C:\ManHour\backup\manhour_%STAMP%.sql
forfiles /p C:\ManHour\backup /m *.sql /d -30 /c "cmd /c del @path"
schtasks /Create /TN "ManHourBooking Backup" /TR "C:\ManHour\backup.bat" /SC DAILY /ST 23:30 /RU SYSTEM /RL HIGHEST /F

This keeps 30 days of backups. Copy the folder to another computer or drive regularly, because a backup on the same disk does not survive a disk failure. To restore: mysql -u manhour -p manhourbooking < manhour_2026-10-26.sql.

10. If something goes wrong

ProblemLikely cause and fix
Other PCs cannot open the addressCheck in this order: the task is running (netstat -ano | findstr :8080); the firewall rule exists and the network profile matches; the IP is correct (ipconfig); from the other PC run PowerShell Test-NetConnection SERVER-IP -Port 8080.
It works on the server but other PCs show "Network error" at loginThe website was built with the old localhost address. Make the change in 3.1 and rebuild the JAR.
Refreshing /admin or /staff shows an error pageSpaController (3.2) or the permit line in SecurityConfig (3.3) is missing. Rebuild after adding them.
The page loads but looks unstyled or blankThe assets folder was not copied into static. Rebuild with the script and check the JAR contents with 7-Zip.
Task is "Running" but nothing listens on 8080Read C:\ManHour\logs\app.log. Common causes: wrong DB user or password ("Access denied"), MySQL not started yet, wrong Java path, port already in use.
"Access denied for user"Password in the start script does not match step 5.2.
"UnsupportedClassVersionError"The Java on the server is older than 17.
Works until the server reboots, then stays downMySQL was not ready. Increase the trigger delay to 2 or 3 minutes and keep the restart-on-failure option.
"Port 8080 was already in use"Another program uses it. Set SERVER_PORT to another number in the script and in the firewall rule.
Task stops after a few daysThe setting "Stop the task if it runs longer than" is still ticked. Untick it.
Date or month looks wrongThe server clock or time zone is wrong. Fix Windows time and time zone.
Task Scheduler "End" leaves java runningCheck with tasklist | findstr java. As a last resort stop the process by its ID: taskkill /PID 1234 /F (do not kill all java processes if other programs use Java).

11. Security checklist for a company network

  • Change the first admin password (ADMIN01 / admin123) immediately, and set your own DEFAULT_PASSWORD.
  • Use your own long JWT_SECRET and a strong database password. Never leave the example values.
  • Allow the firewall rule only for your own subnet (6.2). Do not forward port 8080 on the internet router.
  • The connection is plain HTTP, so passwords can be read by someone who can capture traffic on the network. If that matters, put HTTPS in front (for example IIS with a certificate as a reverse proxy, or Nginx), or ask your IT team.
  • Restrict access to C:\ManHour (the start script and backup.cnf contain passwords) to administrators.
  • Keep Windows, Java and MySQL updated. Test updates after installing them.
  • Keep copies of the JAR, the start script and database backups on another computer.

12. Optional: a real Windows service instead of Task Scheduler

Task Scheduler works, but a Windows service is more robust: it restarts automatically after a crash, is controlled from Services, and handles log files better. Free tools such as WinSW or NSSM wrap the same JAR and start script as a service. The server preparation (sections 3 to 6) stays exactly the same; only section 7 changes.
